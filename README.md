# 포털 메뉴 카드 소팅

한양대학교 인간공학과실습 팀프로젝트의 카드 소팅 웹페이지이다. 별도 빌드 없이 GitHub Pages에서 제공하는 HTML·CSS·JavaScript로 구성했다.

## 현재 상태

- **회의용 시안**이다. `site-config.js`에 임시 메뉴 24개와 짧은 기능 설명을 넣었다.
- 모든 제출은 현재 `is_test: true`로 저장되어 실제 연구 응답과 구분된다.
- 메뉴 범위와 기능 설명, 문항, 참가자 안내는 회의 및 예비 진행 후 확정해야 한다. 기능 설명은 제공받은 메뉴 명칭과 맥락을 바탕으로 작성한 초안이며, 각 실제 페이지의 기능을 모두 검증한 결과는 아니다.
- 실제 연구를 시작할 때 `study.mode`를 `live`로 바꾸고 `study.version`을 새 값으로 변경한다. `?test=1`로 접속하면 live 모드에서도 시험 응답으로 저장된다.

## 참가자 흐름

1. 조사 안내를 읽고 동의한다. 학년·최근 한 달 포털 이용 빈도는 선택 응답이다.
2. 관련 없는 연습 카드 네 개로 선택·묶기·이름 붙이기를 익힌다. 연습 결과는 제출하지 않는다.
3. 명칭과 기능 설명이 있는 카드를 직접 묶고 이름을 붙인다. 묶음 개수는 지정하지 않는다.
4. 뜻을 모르는 기능은 별도로 표시한다. 나머지 카드는 모두 분류하고 비어 있지 않은 묶음에 이름을 붙여야 다음 단계로 진행된다.
5. 분류 기준을 적는다. 어려웠던 기능·여러 묶음에 어울리는 기능과 이유는 선택 응답이다.
6. 결과를 확인해 제출한다. 저장 성공을 확인한 뒤 완료 화면을 표시한다.

이름·이메일·전화번호는 받지 않는다. 카드 순서는 처음 시작할 때 무작위로 정하고, 다시 접속해도 같은 순서와 작성 내용을 복원한다. 같은 브라우저·같은 버전의 완료 응답은 완료 화면을 유지한다. 기기나 브라우저를 바꾸는 고의적 반복 참여 및 두 연구 간 중복까지 차단하는 기능은 아니다.

## 저장 연결

저장 대상은 제공받은 Supabase 프로젝트의 `card_sort_responses`이다. 브라우저에서는 공개용 Publishable key를 사용하며 관리자 키는 포함하지 않는다.

`payload`에는 카드 명칭·설명 전체, 제시 순서, 묶음 이름과 카드 식별자, 뜻 모름 표시, 사전·사후 응답, 동의 여부, 시작 및 클라이언트 제출 시각을 기록한다. 서버 제출 시각은 테이블이 별도로 기록한다. 연습 결과나 개별 클릭 경로는 전송하지 않는다.

전송 시 응답 전체를 동결하고 제출 번호를 유지한다. 네트워크 실패 시 같은 번호와 동일한 본문으로 재시도한다. 첫 요청이 이미 저장된 경우의 고유 번호 충돌은 저장 확인으로 처리한다. 전송 결과가 불확실한 동안에는 내용을 변경할 수 없게 해, 재시도 시 다른 내용이 같은 제출 번호에 붙지 않도록 했다.

## 로컬 확인

이 폴더에서 `python3 -m http.server 8765`로 실행한 뒤 `http://localhost:8765`로 접속한다. 모듈을 사용하므로 `index.html` 파일을 직접 여는 방식은 사용하지 않는다.

## GitHub Pages

저장소 루트의 정적 파일을 `main` 브랜치의 `/`에서 제공한다. `.nojekyll`을 포함한다. 모든 파일 참조는 상대 경로이므로 프로젝트 주소에서도 동작한다. 관리자 설정 SQL, 연구 응답, 원본 메뉴 캡처는 이 웹사이트 저장소에 포함하지 않는다.

## 화면 구성 원칙

- 흰색·네이비·하늘색을 사용하고, 기능 카드와 참가자가 만든 묶음의 위계를 구분한다.
- 휴대전화에서는 미분류 카드와 내 묶음을 탭으로 전환한다. 선택한 카드는 화면 하단의 도구로 이동한다.
- 드래그를 요구하지 않고 버튼 선택과 이동을 기본으로 한다. 키보드 조작, 입력란 이름, 선택 상태 안내를 제공한다.
- 사용자에게 현재 메뉴 경로나 사전 카테고리 이름을 제공하지 않는다.
- 외부 글꼴 서비스나 분석 추적 도구를 사용하지 않는다. 한글 글꼴은 페이지와 함께 제공한다.
